work down `SCOPE.md`'s "Not yet ported" list toward a full port. Each item
landed as its own commit, after the full workspace gate (tests, clippy

## Changes a caller can see

- **Breaking:** `WorkflowEvent::AgentRun` carries the agent's `input`.
- `SupportsAgentRun::description()` (defaulted) and `Agent::tools()`.
- File-access and file-memory edits share one lock per store and folder.

## Found along the way

- The Python `redis` package has a RediSearch vector store this port
  lacked and `SCOPE.md` did not list; it is now listed.
- Valkey upstream is a .NET history provider, not a vector store; `SCOPE.md`
  had it under vector stores.

## Still open, and why

See `SCOPE.md`. In short: FIDES (≈4,900 lines of information-flow control,
not started), Agent-hooks remainder, Foundry hosting and server-hosted
agents, Content Understanding, the App Insights exporter, the remaining
vector stores (MongoDB, DuckDB, SQL Server, Redis; DocumentDB blocked),
function-invocation mixed batches, the depth gaps (skills sources,
compaction groups, workflow telemetry/cancellation, message injection,
per-call history persistence, providers seeing the agent), MCP 2.x, and
workflow pause/restore bookkeeping. Three remain blocked outright: Durable
Task (sidecar protocol), the Claude Agent SDK shim, and the Cosmos memory
provider. #9768 stays a deliberate decision.
