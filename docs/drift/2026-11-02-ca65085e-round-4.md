# Round four against `ca65085e`: clearing the queue (same upstream baseline)

The fourth follow-up against the same baseline as
[`2026-11-02-ca65085e`](2026-11-02-ca65085e.md). Asked to fix as much as
possible, this round takes the two security items earlier rounds had left
for a decision, then the standing items and the rest of the queue. Nine

Verified before commit: full workspace build, `cargo test --workspace
--all-features`, `cargo clippy --workspace --all-features --all-targets

## A correction to the first pass

The 2026-11-02 pass said `agent-framework-copilotstudio` "sends no
framework `User-Agent`". That was wrong. It set one per request, in a
one-off format (`agent-framework-rs-copilotstudio/<version>`), and so did

earlier audit counted bare `reqwest::Client::new()` calls and missed the
per-request header. A loopback test written for this round caught it. Both
crates now send the shared format; see below.

## Security

### Redis: one scope's memories could be returned under another's

The defect recorded in the first pass. Scope `TAG` fields are indexed with
RediSearch's defaults (separator `,`, case-insensitive) over the
unescaped stored value, so `@user_id:{smith}` matched an entry stored under
`user_id = "smith,john"`, and `"Alice"` matched `"alice"`'s. The reverse was
broken too: a provider scoped to `"smith,john"` queried for one tag spelled
`smith,john`, which the index never created, so it could never find its own
memories.

Upstream (#9461) rewrote storage around hashed scope tokens and shipped it
as `[BREAKING]` with a migration. This fix needs neither:

- **The query is treated as a candidate filter.** A scope value is split the
  way the index split it, and every part is required
  (`@user_id:{smith} @user_id:{john}`), which restores the under-match.
- **Every hit is re-checked against the exact scope** (`exact_scope_hits`,
  using the same `Scope::matches` the SCAN fallback has always used), which
  closes the leak. Results keep their rank order.
- **Over-fetch.** `FT.SEARCH` is asked for `limit × 4` candidates, so hits
  the check drops cannot crowd genuine ones out of the page.

There is no schema change and no data migration; existing indices and
entries keep working. Both read paths now agree on what a scope is.

**Limit of the verification:** this environment's Redis is 7.0 without
the search module, so the `FT.SEARCH` path could not be run end to end. The
two pure pieces it is built from — the query builder and the exact re-check
— are unit-tested, including the leak case. The 21 integration tests
(SCAN path) pass.

`crates/agent-framework-redis/src/context_provider.rs`; tests
`a_scope_value_containing_the_tag_separator_queries_every_part`,
`a_scope_value_of_only_separators_adds_no_clause`,
`another_scopes_memory_matched_by_the_tag_query_is_not_returned` and
`exact_scope_hits_keeps_rank_order_and_the_limit`.

### AG-UI: a failed run's internal error text reached the client

The DevUI surface stopped echoing run errors in the first pass (upstream
#9460), and AG-UI was left for a decision because upstream had not changed
its own AG-UI surface. Its four `RUN_ERROR` sites put `e.to_string()` — a
provider's raw HTTP body, a tool's error text, internal type names, a
filesystem path — in front of the client. They now go through the same
`log_run_failure` as DevUI: the client gets a fixed message and the detail
is logged against the run id, gated on `ENABLE_SENSITIVE_DATA`. The hosting
layer's own coded `RUN_ERROR`s (a missing resume entry, an unavailable
snapshot store) are contract messages and are unchanged.

The existing test `agent_failure_emits_run_error` asserted the disclosure
(`message` contains the agent's internal `"kaboom"`); it now asserts the
opposite.

`crates/agent-framework-hosting/src/{agui,devui/mod}.rs`.

## Defects

### Transport errors did not say what went wrong

Thirty sites across the provider crates wrapped a `reqwest` failure as
`format!("request failed: {e}")`. `reqwest::Error`'s `Display` prints only
its outermost layer, "error sending request for url (…)", which is identical
for a timeout, a refused connection, a DNS failure and a TLS error. The
cause is in `source()`. A new `agent_framework_core::error::error_chain`
renders the whole chain (skipping a layer the previous one already
contains), and every one of those sites uses it. It needs only
`std::error::Error`, so core still has no `reqwest` dependency.

The first pass's Foundry timeout test had to measure elapsed time *because*
the error could not say "timeout". It now also asserts that the message
names the timeout, which fails without this change.

### A zero MCP request timeout failed every call (#9314)

`Duration::ZERO` makes `tokio::time::timeout` fail each request the moment
it is sent, so the tool connected and then failed on its first call with an
error naming the method, not the misconfiguration. All three tool types now
refuse it in `connect`, before any process is spawned or connection opened,
as upstream does; the builder setters stay infallible. Tests point each tool
at something unreachable, so a test only passes if the configuration error
comes first.

### MCP tools that require the Tasks extension were offered anyway (#9746)

This client does not implement MCP Tasks, so a tool whose
`execution.taskSupport` is `"required"` cannot be called — the server
refuses a plain `tools/call` — yet it was offered to the model like any
other, and every call to it failed. It is now skipped with a warning, as
upstream does. `"optional"` Tasks support is an ordinary tool, which is
what #9746 itself establishes and what this client already did (it never
read the field at all).

### Anthropic document citations' regions were not text offsets (#9436)

Anthropic's `char_location`, `page_location`, `content_block_location` and
`search_result_location` citations locate the quote in the *cited source*:
characters, pages or blocks of the document. They were stored in
`Annotation::annotated_regions` with nothing distinguishing them from spans
of the answer, so a consumer highlighting the answer from them highlighted
the wrong text or ran past its end. `Annotation` gains
`annotated_regions_coordinate_space` (`Content` / `Source`; absent means
`Content`, so existing serialized annotations read the same), Anthropic
sets `Source`, and `Annotation::content_regions()` returns only spans of the
text. This port's hosting surfaces never turned regions into output spans,
so upstream's adapter half did not apply.

## Standing items closed

### A framework `User-Agent` from every crate

`SCOPE.md` held this open because "a framework-wide header needs the helper
somewhere every crate can reach, and `agent-framework-core` carries no
`reqwest` dependency". The *format* does not need `reqwest`: it is a string.
`agent_framework_core::user_agent::user_agent(component, version)` now owns
it (`agent-framework-rust/<version> (<component>)`, unchanged), the Azure
crate's `azure_user_agent` delegates to it, and each provider crate builds
its client with a small local `http_client()`. That covers 22 construction
sites in 12 crates. The three builder-based clients (A2A's timed client, the
AG-UI client, the MCP HTTP transport) set it too; A2A's `with_timeout`
rebuilds its client and would otherwise have dropped it.

Tests: `requests_carry_the_framework_user_agent` for OpenAI, which genuinely
sent none before, and for Copilot Studio (see the correction above).

### `SequentialBuilder::ensure_trailing_user_turn` (#8779)

Some chat-completions providers answer a prompt ending on `assistant` with
empty text, and in a sequential pipeline every participant after the first
is handed one. The option appends upstream's `"please continue."` user turn
to an **invocation-only copy**, so it is never forwarded, yielded or seen by
another participant. Off by default. Implemented on `AgentExecutor` and
`AgentApprovalExecutor` (`with_trailing_user_turn`), so other builders can
use it too.

### Per-agent autonomous handoff (`with_autonomous_mode`)

`HandoffInteractionMode::Autonomous` is a single shot. Upstream's
autonomous mode re-runs an agent that answered without handing off, with a
continuation prompt, until a per-agent turn limit, and only then returns
control to the user. `HandoffBuilder::with_autonomous_mode(AutonomousMode)`
ports that:

- by default it applies to every participant, or `for_agents` names them;
- the prompt and turn limit can be set per agent (defaults: upstream's
  "User did not respond. Continue assisting autonomously." and 50);
- a limit of `0` disables continuation for that agent;
- the count resets on a handoff.

It composes with either interaction mode: once an agent's turns are used up,
the mode's own step follows. Continuations still count toward
`max_iterations`, which bounds the whole run.
